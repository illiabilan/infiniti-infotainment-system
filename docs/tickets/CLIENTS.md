# Клієнтська частина: CL-1 – CL-5

Джерело: `docs/design/clients.md`. Епік: `EPIC.md`. Рішення: D2, D7, D8, C8, H4, K1 – K4, CL1 – CL4.

Порядок: CL-1 і CL-2 першими, без них клієнти не мають джерела правди. Далі CL-3, CL-4, CL-5 паралельно, після Z4 і Z7.

| Тікет | Назва | Залежить від |
|---|---|---|
| CL-1 | Міграція CAN і VehicleState у Кор | немає |
| CL-2 | Процес Кора: WebSocket-сервер і життєвий цикл | CL-1 |
| CL-3 | Деш: мінімальний клієнт (H4) | CL-2, Z4 T2, CQ6 |
| CL-4 | Кластер: клієнт (K2, K3) | CL-2, Z7 T2, Z4, CQ4 |

## CL-1: Міграція CAN і VehicleState у процес Кора

Контекст: зараз `dashboard/main.cpp`, `climate/src/main.cpp`, `emulator/src/main.cpp` кожен створює свій CAN-бекенд і свій `VehicleState`. Тричі незалежні власники CAN суперечать C8 і D2.

Область: `dashboard/`, `climate/`, `cluster/`, `emulator/`, `core/`.

АС:
- [ ] Grep `SocketCanBackend\|MockCanBackend` у `dashboard/`, `climate/`, `cluster/` повертає порожньо. Створення перенесено в Кор.
- [ ] Один `VehicleState` створюється в процесі Кора. Інші процеси його не створюють. Емулятор виключено, бо він імітує шину авто (рішення власника).
- [ ] Значення RPM, швидкості і клімату після міграції збігаються з еталонним сценарієм емулятора (порівняння виводу двох прогонів).
- [ ] Існуючий `core_test` проходить.
- [ ] До появи CL-2 застосунки можуть тимчасово отримувати дані через локальний IPC-міст, це описано в тікеті.
  - Примітка: CL-1 і CL-2 поставляються разом, тому мостом слугує канал `vehicle` WebSocket з CL-2 (`clients.md`, розділ 4.4). Окремого тимчасового моста немає.
- [ ] Жоден файл не перевищує 700 рядків.

## CL-2: Процес Кора: WebSocket-сервер і життєвий цикл

Контекст: Кор має бути окремим процесом, що володіє USB, AA-сесією, CAN і станом авто. Протокол описано в `clients.md`, розділ 4.

Область: новий процес у `core/` (наприклад `core/app/`).

АС:
- [ ] Кор приймає `hello` і відповідає `snapshot` (розділ 4.1 `clients.md`).
- [ ] Кожне повідомлення має `"v":1`. Повідомлення з іншою версією відхиляються з кодом помилки.
- [ ] Сервер прив'язаний лише до `127.0.0.1` (перевірка `ss -ltn`).
- [ ] Відключення клієнта не закриває AA-сесію. Перевірено трасою.
- [ ] Перепідключення клієнта отримує `snapshot` і keyframe.
- [ ] Кор не перезапускається між сесіями (PID без змін).
- [ ] Порт визначено за CQ5 і записано в конфіг.
- [ ] Тести протоколу: один сценарій hello/snapshot, один сценарій хибної версії. Більше не потрібно.

## CL-3: Деш, мінімальний клієнт (H4)

Контекст: H4 вимагає, щоб екран AA в Деші був клієнтом Кора. Повний Деш не входить у цей тікет. Зараз `dashboard/` працює на моках (погода, медіа, навігація).

Область: `dashboard/`, нові файли. Код із `cppqtdev/professional-vehicle-dashboard` не копіюється (D7).

АС:
- [ ] Відео AA (потік `main`) видно на екрані 1920x1080.
- [ ] Затримка від кадру до показу виміряна і записана в тікеті.
- [ ] Тап по відео надсилає `input` з `display_id: "main"`. Кор отримує подію (Z5 T4).
- [ ] Стан сесії (`idle`, `streaming`, `closed`) відображається.
- [ ] Порівняння з upstream-репо показує відсутність спільного коду (grep за унікальними рядками).
- [ ] Жоден файл не перевищує 700 рядків.

## CL-4: Кластер, клієнт (K2, K3)

Контекст: кластер показує навігацію з першого кроку (K2). Кластерне відео (K3) у режимі повного або часткового виводу. Вибір режиму фіксується конфігом (K4).

Область: `cluster/`.

АС:
- [ ] Маневр, дорога і відстань до маневру видно при активній навігації.
- [ ] При `active=false` блок очищується.
- [ ] Режим відео (full або partial) вибирається конфігом. Partial використовує `view_area` і `safe_area`.
- [ ] Базові гейджі кластера (K1) не змінені. Перевірка: чек-лист 10 пунктів з `docs/traces/README.md`, або порівняння скріншотів.
- [ ] Кластер не відкриває CAN (grep порожній).
- [ ] Тач кластера вимкнено за замовчуванням, поки не вирішено CQ4.
- [ ] Жоден файл не перевищує 700 рядків.

## CL-5: Клімат, клієнт навігаційного блоку (CL4)

Контекст: у навігаційному режимі годинник переходить у правий верхній кут, а в блоці показується навігація (CL4). Анімація переходу (CL3) цим тікетом не покривається. Вона окрема.

Область: `climate/`.

АС:
- [ ] У навігаційному блоці видно маневр, відстань і ETA.
- [ ] При `active=false` блок повертається до годинника.
- [ ] Кліматичні функції (CL1) не змінені. Наявні QML-тести в `climate/` проходять.
- [ ] Клімат не відкриває CAN (grep порожній).
- [ ] Анімація переходу (CL3) задокументована як окремий тікет.
- [ ] Жоден файл не перевищує 700 рядків.
